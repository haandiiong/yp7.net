## 使用风险提示

**IPLC、IEPL、BGP、直连和中转不是一张从差到好的等级表。** 直连、中转描述代理连接结构；BGP是路由协议；CN2是特定运营商网络；IPLC、IEPL则是运营商提供的专线产品概念。它们可以出现在同一条连接的不同环节。

机场在套餐中写了某个名词，只能先记为商家说法。是否采用所述承载、覆盖哪段路径，以及你的实际体验如何，需要分别找证据。本文不对下列机场作线路真实性认证；详情页的推广关系也不构成技术证明。

## 先看这些词分别在说什么

| 线路词 | 描述的对象 | 仅凭这个词不能判断什么 |
|---|---|---|
| 直连 | 机场语境中，客户端直接连接所选代理服务器，未另设商家声明的中转入口 | 不代表途中没有路由器，也不代表一定便宜、慢或容易拥堵 |
| 中转 | 客户端先连入口，再由入口转发到后续代理或出口 | 不说明入口到出口用了公网还是专用承载，也不保证更低延迟 |
| BGP | 网络之间交换可达路由、按策略选路的协议 | 不等于自动测出最快线路，也不证明接入了多少运营商 |
| CN2 | 中国电信的特定骨干网络，官方标识为AS4809 | 节点名称含CN2，不证明用户到目的服务的全程都经过该网络 |
| IPLC | International Private Leased Circuit，国际私有租用电路；具体交付按运营商产品与订单约定 | 不代表机场给每名订阅用户独占该电路或带宽 |
| IEPL | International Ethernet Private Line，国际以太网专线，以以太网方式提供站点间连接 | 不代表从家中设备到目的网站全程都是专线，也不保证应用可用性 |
| 专线、精品网、优化线路 | 套餐中可能使用的概括或宣传词 | 没有具体承载、覆盖区段和服务约定时，无法据此比较质量 |

直连、中转在这里是代理服务的描述方式，并非对所有商家都统一的技术规格。IPLC、IEPL的运营商产品定义和BGP标准依据见下文。

## 把实际连接分成几段

可以先按“设备 → 本地接入网络 → 机场入口 → 机场出口 → 目的服务”理解一条连接。直连服务的入口、出口可能在同一台代理服务器；中转服务则可能增加入口与出口之间的转发环节。每段仍有自己的路由、容量和故障点，去程与回程也不一定相同。

因此，购买前应问清“专线”指入口到出口的哪一段、哪些节点和套餐可以使用，是否包含备用公网路径。没有这些信息时，把实际承载记为未核验，不能由节点名补全整条路径。

价格、时延和晚高峰表现也要分开比较。同样叫直连的服务可以有不同资源和定价；增加中转环节可能改变路径，也可能增加转发负担。线路标签本身不决定售价或性能。

## BGP与CN2：协议、网络和质量不是一回事

BGP用于自治系统之间交换网络可达信息，路由选择受本地策略影响。它不是以实时测速寻找最低延迟路径的保证。商家所谓“BGP优化”还需要说明接入运营商、入口、选路策略与适用网络；写出BGP三个字不能证明多运营商适配更好。技术定义依据[IETF RFC 4271第3节与第9.1节](https://www.rfc-editor.org/rfc/rfc4271.html)。

CN2是中国电信运营的网络，官方Global IP Transit资料将其标为AS4809。它和BGP不在同一分类中：一个是网络名称，一个是协议。官方运营商产品的说明，不能直接转化为某家机场的全程路径或用户体验保证。参见[中国电信欧洲Global IP Transit](https://www.chinatelecomeurope.com/product/global-ip-transit/)。

## IPLC与IEPL：先核对产品，再看机场如何使用

IPLC的全称是International Private Leased Circuit。以Singtel产品为例，它提供站点间的第一层点对点专用连接，并列明带宽与保护选项。IEPL的全称是International Ethernet Private Line；中国电信官方资料介绍的是以以太网提供的端到端连接，可有点对点或点对多点形态。具体产品的接口、带宽、保护和交付范围需要看订单，不能只靠缩写判断。参见[Singtel IPLC](https://www.singtel.com/business/products-services/connectivity/global/iplc)与[中国电信IEPL产品资料](https://www.chinatelecomeurope.com/wp-content/uploads/2025/09/IEPL-Connectivity.pdf)。

**运营商向客户交付的专线，与机场向订阅用户出售的服务，是两个层面的产品。** 即使某段采用了专线，机场的接入、转发、出口服务器及共享容量仍影响端到端体验。中国电信的[IEPL/IPLC服务条款第2、3节](https://www.chinatelecomglobal.com/sc/footer/detail/37463)也把电路类型、接口、带宽和服务地点落实到订单；本文未取得能核验下列机场具体交付范围的资料。

晚高峰测速可以回答“这个节点在这个时间、这套环境下表现怎样”，不能回答“它是否租用了真实IPLC/IEPL电路”。低延迟、高下载速度、路由中出现某个AS或商家提供一张拓扑图，都不能单独完成线路认证。

## 购买前如何验证自己关心的部分

1. **先写清订单。** 记录具体套餐、一次付款金额、付款周期、每月或总流量、重置日、设备/IP限制、试用与退款。不能把年付折算月价当成可月付价格。
2. **再核对可用节点与倍率。** 问清该档能用哪些节点、扣量规则与更新时间；倍率是计费约定，高倍率本身不能证明线路成本或技术等级。
3. **确认客户端能完成同一用途。** 先检查是否有通用订阅、支持什么配置格式；只能使用专属客户端的服务，不默认支持第三方软件。需要安装入口可看[科学上网工具与客户端下载](/posts/airport-tools/)。
4. **用自己的环境检查体验。** 尽量固定设备、客户端、运营商与接入方式，记录日期、时段、节点及测速工具；比较常用时段的多次结果，也记录失败和中断。只在白天测试不能推定晚高峰表现，换了网络也不能直接横比。
5. **分别验收应用。** 测速结果之外，再检查常用网页、视频、AI工具或会议能否完成实际任务。Speedtest跑得快不代表某个平台可用；单次成功也不是长期保证。

已有样本缺少的信息不能靠推断补齐：没有丢包数据就不写“零丢包”，没有所购套餐信息就不标成某档实测。测试方法与来源关系见[本站方法说明](/methodology/)；下单步骤见[机场购买教程](/posts/jichang-buying-guide/)。

## 常见问题

### IPLC 一定比中转好吗

两者并非互斥类别：中转描述转发结构，IPLC描述可能采用的承载产品，中转服务也可能宣称使用IPLC。先核对具体套餐与覆盖区段，再比较相同环境下的体验，不能仅凭这两个名称排序。

### 专线机场一定适合流媒体吗

不一定。线路承载与平台可用性要分开验证，流媒体还涉及出口IP、DNS、账号地区与平台策略。写了IPLC或IEPL不能保证Netflix、Disney+等平台当前可用或长期可用。

### 高倍率能证明是真专线吗

不能。倍率是服务商制定的流量扣除规则，不能单独证明采购成本、带宽或承载类型。也不要反过来认为1倍率就没有专线；具体节点如何扣量，以该套餐的明确规则为准。

### 新手需要追求 IPLC/IEPL 吗

先按设备兼容、用量、付款周期和常用任务筛选。若有试用，先验证自己的网络；没有试用或退款时，把付款周期与可能无法满足需求的成本一并考虑。没有证据时，不为线路缩写预设更高质量。

### 通过路由追踪能认证IPLC或IEPL吗

不能单靠一次路由追踪认证。它最多补充该次探测能看到的路径信息，不能完整展示机场内部承载、订单交付范围或共享方式。本文的性能记录与技术定义分别阅读，不把二者拼成线路认证结论。

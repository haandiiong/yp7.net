**Clash Mi 是使用 Mihomo 内核的代理客户端，安装后还需要你自己的兼容配置。** 在 iPhone 或 iPad 上，基本顺序是：安装应用 → 获取 Clash 配置链接 → 添加并选中配置 → 开启连接 → 选择节点并验证访问。免费应用不附送机场套餐，也不能把服务商注册页当作订阅地址。

本页更新于2026年10月15日，依据[官方用户手册](https://clashmi.app/guide/)、[常见问题](https://clashmi.app/guide/faq)与公开源码整理，**未在 iPhone/iPad 上安装实测，也未验证任何机场的当前连接或性能**。本文用中文菜单名称说明操作；其他语言、后续版本和服务商定制配置的界面可能不同。

## 先确认版本、系统与费用

## 第一步：从官方入口安装

1. 在 iPhone/iPad 打开[项目仓库](https://github.com/KaringX/clashmi)或[唯一官网 clashmi.app](https://clashmi.app/)，进入其 App Store 链接。核对应用名 **Clash Mi** 和应用编号 **6744321968**，避免同名下载站。
2. 用自己可管理、且能获取此应用的 Apple 账号完成下载。若商店显示当地不可用，先核对账号地区与商店条件；不要把“搜不到”直接判断成手机不支持。
3. 下载后打开应用。新用户优先使用商店稳定版；TestFlight 是另一个发布渠道，并非免费节点入口。切换商店版和测试版前先备份自己的配置。

官方说明商店版和 TestFlight 版会相互覆盖；本文按商店安装后的基础流程写，不要求安装测试版。[官方安装说明](https://clashmi.app/guide/#一、-下载)

## 第二步：拿到能用的配置格式

Clash Mi 运行 **Clash/Mihomo YAML 配置**。先在你自己的服务商后台找“Clash”“Mihomo”或明确标注 Clash Mi 的配置入口；不确定时向服务商确认返回的配置格式。

| 你手里的内容 | 能否直接按本文导入 | 下一步 |
|---|---|---|
| 返回 Clash/Mihomo YAML 的订阅 URL | 可按下文添加链接 | 完整复制自己账号的链接 |
| 兼容的 `.yaml` / `.yml` 配置文件 | 可走文件导入 | 文件导入后，更新方式与远程链接不同 |
| 服务商注册页、官网导航或登录页面 | 不能代替订阅 | 登录后台取得配置链接 |
| V2Ray订阅、sing-box JSON或单条节点分享文本 | 不能当作同一种配置直接粘贴 | 优先索取 Clash/Mihomo 格式，不只修改扩展名 |

订阅 URL 不一定以 `.yaml` 结尾，关键是服务端实际提供的配置。不要只修改文件名或链接后缀来“转换格式”；即使添加成功，也仍需检查节点、规则与当前版本是否兼容。[官方格式说明](https://clashmi.app/guide/faq#订阅添加失败)

订阅地址通常带有个人凭据。只复制自己的链接，不公开贴到评论、截图或陌生转换网站；需要服务商处理格式时，优先使用其官方入口。

## 第三步：添加配置链接

1. 打开 Clash Mi 首页的 **“我的配置”**。
2. 点击右上角 **“＋”**，选择 **“添加配置链接”**。
3. 在 **“Clash配置链接”** 输入框粘贴完整订阅 URL。不要混入说明文字、引号或换行后的另一条地址。
4. 填写便于识别的 **“备注”**，例如服务商名称和用途；不要用账号密码作备注。
5. 点击右上角的 **对勾保存图标**，等待下载结果。出现错误时，先保留错误文字并对照下文，不要只重复保存。

对勾即保存按钮；添加后应能回到配置列表检查结果。菜单路径可对照[官方使用流程](https://clashmi.app/guide/#二、快速使用-quickstart)。

“＋”菜单还有 **“从剪贴板导入”“扫描二维码”“导入配置文件”**。剪贴板或二维码只是输入入口，不会让不兼容格式自动变成 Clash 配置。持有本地 YAML 时可选文件导入；需要随服务商更新节点的用户，优先使用服务商提供的远程配置链接。

## 第四步：选中要运行的配置

添加完成后，在“我的配置”列表中 **点击要使用的那条配置**，再返回首页，核对“我的配置”下显示的名称是否正确。列表里有一条配置，不等于它就是当前要运行的配置；多个服务商同时存在时更需要检查。

若列表里已有旧配置，不要跳过点选。主动检查首页名称，可以避免“添加了新订阅，仍运行旧配置”。

远程配置需要更新时，打开该条目的更多菜单，选择 **“更新”**。更新后再次核对当前配置及连接状态；已连接时，按应用提示重新连接，使新配置实际生效。不要只看下载成功就认定现有连接已换用新节点。

## 第五步：开启连接，再检查代理组

1. 返回首页，确认显示的是刚选中的配置。
2. 按服务商配置说明选择模式。**规则**按配置中的规则分流，**全局**使用全局代理选择，**直连**不等于已经通过节点连接；初次不必同时改动覆写、DNS与规则。
3. 打开首页连接开关。如果 iOS/iPadOS 首次弹出添加 VPN 配置一类的授权提示，核对请求来自 Clash Mi，再允许并按系统要求完成验证。
4. 等待首页显示 **“已连接”**。持续“连接中”或立即断开时，记录错误信息，先按下文检查配置，不用反复添加同一链接。

系统授权的具体弹窗取决于设备与已保存的 VPN 配置。完成授权后仍需回到应用检查状态，不能只看到开关打开就结束。

连接后可从首页 **“面板”** 进入内置控制面板，在 **“代理”** 中检查你实际使用的代理组，并按配置提供的节点选择。组名由服务商配置决定，不一定叫“节点选择”。如果选了 `DIRECT`，相关流量仍会直连；若使用“全局”却无法访问，尤其要检查 `GLOBAL` 指向的内容。官方 FAQ 说明其全局选择可能仍是直连。[面板入口](https://clashmi.app/guide/online-panel)、[全局模式说明](https://clashmi.app/guide/faq#全局模式无法连接)

## 第六步：确认真正能用

完成连接后，依次验证：

1. **配置对得上：** 首页名称与自己选择的配置一致，应用显示已连接；不能只凭 VPN 图标判断节点可用。
2. **真实网站能访问：** 打开一个自己平时使用的网站，换另一个网站交叉检查。只有某个网站失败时，不立即把全部订阅判为失效。
3. **目标应用能完成操作：** 若要使用 AI、视频或办公应用，实际检查登录、对话、播放或工作流程。延迟数字不等于下载速度，也不能代替目标平台验证。
4. **换网络后复查：** 需要在 Wi-Fi 和蜂窝网络之间切换时，重新检查连接与访问；保留当前配置和节点名称，便于定位差异。

这里是用户自己的验收顺序，不是本站对某个机场的可用性保证。节点地区选择见[地区与用途对照](/posts/proxy-node-region-guide/)，大流量测试前先看[测速方法与流量消耗](/posts/speedtest-vpn/)。

## 常见错误：按表现定位

| 表现或错误 | 优先检查 | 接下来怎么做 |
|---|---|---|
| 商店找不到或不能下载 | 账号地区、系统要求、官方应用编号 | 从官方链接进入自己的商店页，核对提示 |
| `Invalid format: html` | 链接返回的是网页，可能复制了登录或注册页 | 回后台复制正确配置 URL；不要把 HTML 改名成 YAML |
| `proxies and proxy-providers not found` | 返回内容缺少 Clash 配置所需条目，或拿错了格式 | 向服务商确认 Clash/Mihomo 订阅，核对账号是否可领取配置 |
| 已添加，但首页名称没变化 | 新配置没有选为当前配置 | 回“我的配置”点选该条目，再检查首页名称 |
| 连接时出现 `yaml: line` 等配置报错 | 配置语法、规则或内核兼容问题 | 更新官方配置；保留错误行信息让提供方核对 |
| 已连接，但网站打不开 | 所用代理组、节点、规则及本地网络 | 先换一个已确认可用的节点和网站，逐项比较 |

格式错误由[配置检查源码](https://github.com/KaringX/clashmi/blob/v1.0.31.1703/lib/app/modules/profile_manager.dart#L556-L574)给出；连接时的 YAML 报错及服务商下发格式问题另见[官方 FAQ](https://clashmi.app/guide/faq)。

### 订阅下载失败，是否要改UserAgent？

先核对完整链接、账号条件和可达性。只有服务商明确要求、或确认它因客户端识别下发了其他格式时，再依据其文档调整 **“应用设置 → UserAgent”**；不是所有下载失败都能靠换这个字段解决。修改后重新下载配置，再检查实际返回结果。

如果只是订阅域名当前不可达，先确认本地网络和服务商公告，再使用自己已有的可用连接下载配置。不要从不明来源寻找“万能订阅”。[官方订阅排错](https://clashmi.app/guide/faq#订阅添加失败)

### iPhone连接后马上断开，或者部分App无网络

先记录错误与所用配置，检查是否刚增加了大量规则或修改了覆写。官方 FAQ 提醒 iOS 的 VPN 扩展有内存限制；这种情况需要配置提供方协助减少资源占用，而非重复安装就一定能解决。

仅部分 App 不通时，保留原配置，先换节点与目标 App 交叉验证；再对照官方 FAQ 的 TUN 与 HTTP 代理说明，一次只改一项并重新连接。不要把桌面端“管理员运行”的操作套到 iPhone 上。[iOS与应用连接问题](https://clashmi.app/guide/faq)

### 更新、换客户端之前需要保存什么？

记下当前版本、配置名称与自己的订阅领取位置。导出或备份配置时按私人凭据保存；提供排错截图前遮住订阅 URL、账号和令牌。其他客户端需要什么格式，应以服务商对应入口为准，不把 Clash Mi 配置直接当作 Shadowrocket、sing-box 的通用文件。

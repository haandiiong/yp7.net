更新时间：2026年10月7日（补充OpenWrt二级路由的配置、验证与回滚步骤）

路由器翻墙是把代理或VPN配置放在网络出口，让接入这条路径的设备共用连接策略。**本文采用“现有主路由＋OpenWrt二级路由”的双网段示例**，先接一台测试设备，确认正常后再增加设备。它与同一网段内手动改网关的旁路由不同。

本示例依据官方文档整理，尚未提供本站对应硬件的实测记录。适用环境为OpenWrt 25.12系列、LuCI管理界面、默认firewall4/nftables防火墙和OpenClash。新版本的包管理器、菜单和依赖可能变化，应同时核对[OpenWrt版本说明](https://openwrt.org/releases/25.12/notes-25.12.0)和[OpenClash发布说明](https://github.com/vernesong/OpenClash/releases)。

## 一、什么是路由器翻墙

本示例的IPv4数据路径为：

```text
宽带/光猫 → 现有主路由（192.168.1.1）
                  ├─ 原Wi-Fi与原有设备：保持原连接
                  └─ LAN口 → OpenWrt WAN口（DHCP获取192.168.1.x）
                                  └─ LAN口（192.168.20.1）
                                      → 测试电脑（192.168.20.x）
```

OpenWrt依据订阅规则决定哪些连接直连、哪些交给代理节点。只有接在OpenWrt下游、并以它为网关的设备受此配置影响。主路由原Wi-Fi上的手机不会自动跟随。

示例使用两个不同网段，通常会形成双重NAT，可能影响端口映射、游戏联机和上游NAS发现；不是所有家庭都需要采用这个结构。OpenWrt官方也要求避免[LAN与WAN地址范围重叠](https://openwrt.org/docs/guide-quick-start/troubleshooting_internetconnectivity)。

## 二、2026三种主流路由器翻墙方案

| 方案 | 适用前提 | 需要核对 |
|---|---|---|
| 原厂VPN客户端 | 确切型号和固件已有客户端功能，服务商提供对应配置 | 支持的是VPN客户端还是服务器，具体协议、性能和导入格式 |
| OpenWrt作为主路由 | 硬件受支持，可以承担宽带接入、DHCP及防火墙 | 固件镜像、恢复方法、拨号信息和全家断网影响 |
| 保留主路由，增加代理设备 | 希望先让少数设备接入 | 本文二级路由需双接口和独立网段；同网段旁路由需另行配置网关、DHCP与回程路径 |

旁路由不等于最稳定，也不是安装一个插件就能自动生效。它描述设备的部署角色；软路由描述用通用硬件和软件实现路由的方式。详见[软路由与旁路由的区别](/posts/soft-router-guide-2026/#九、软路由-vs-旁路由-重要区别)。

## 三、路由器翻墙的优势

设备接入配置好的下游网络后，可以共用规则和订阅，适合无法安装客户端的部分电视或游戏设备，也便于统一查看连接记录。但电视、投屏、游戏和IoT是否正常仍要分别验证。

代理或VPN只保护其实际承载的流量；不能据此承诺全网匿名、安全或所有应用都经过加密隧道。

## 四、路由器翻墙的缺点

需要维护固件、依赖、DNS和订阅。性能受协议、CPU、内存、网卡、规则数量和上游线路共同影响；主路由部署失败还可能影响全家上网。二级路由便于先测试，但增加一个网段也带来双重NAT和跨网段访问成本。

## 五、路由器选购标准

本示例需要一台已安装受支持OpenWrt稳定固件、可以登录LuCI、拥有两个可独立配置有线接口的设备，以及一台有线电脑。接口名称可能是`eth0/eth1`、`wan/lan`或其他名称，必须依据该型号资料识别，不能直接套用别人的端口名。

建议留足存储空间安装OpenClash及内核；512MB内存、可用存储256MB以上可作为轻量部署的起点，属于本文容量建议，不是项目保证的最低要求。若需要大量规则或并发，应增加余量，观察实际CPU、内存及存储占用，不以CPU频率承诺千兆速度。

还需要服务商明确提供的Clash/Mihomo兼容订阅或配置文件。邀请码注册入口、登录页面、OpenVPN文件和WireGuard配置不能直接当作Clash订阅。

## 六、2026翻墙路由器选择与兼容性核对 {#六、2026翻墙路由器推荐}

不要仅凭“华硕、小米、华为、TP-Link”等品牌判断能否安装OpenWrt或运行VPN客户端。购买或刷写前逐项核对：

1. 找到完整型号和硬件版本，在[OpenWrt设备列表](https://openwrt.org/toh/start)查询对应设备页。
2. 用[官方固件选择器](https://firmware-selector.openwrt.org/)选对设备及稳定版本，确认首次安装镜像和升级镜像的区别。
3. 按该设备官方安装说明检查网口、无线、存储、启动方式及恢复方法。没有对应说明的机型不要套用同品牌教程。
4. 原厂VPN方案则查厂商该型号的支持文档，确认是客户端功能，以及是否支持所需协议。

本文从**已经安装OpenWrt且网络接口受支持**开始，不提供跨型号通用刷机命令。x86镜像写盘、厂商路由器首次刷写和LuCI系统升级属于不同操作，不能混用。

## 七、路由器翻墙配置教程

### 1. 记录原网络并备份

记录主路由IP、网段和DHCP范围，确认原Wi-Fi能正常上网。下文假设主路由为`192.168.1.1/24`；如果你家不同，修改示例，同时让OpenWrt LAN避开所有已用网段。

先让电脑单独连接OpenWrt LAN，暂不接WAN。依据设备页面或当前配置打开管理地址，设置管理员密码。在“系统 → 备份/升级”生成配置备份并保存到电脑；更改接口前再备份一次。官方[备份与恢复文档](https://openwrt.org/docs/guide-user/troubleshooting/backup_restore)说明，这类备份保存配置，并不是整块磁盘或已安装插件的完整副本。OpenClash配置也应单独导出。

### 2. 配置LAN、DHCP与客户端DNS

在“网络 → 接口”编辑LAN，设为静态地址：

| 项目 | 本示例值 | 说明 |
|---|---|---|
| IPv4地址 | `192.168.20.1` | OpenWrt管理地址、下游网关及DNS |
| 子网掩码 | `255.255.255.0` | 下游网段为`192.168.20.0/24` |
| LAN的IPv4上游网关 | 留空 | 默认路由从WAN获取，不把LAN指向自己 |
| LAN DHCP | 启用 | 不勾选“忽略此接口” |
| DHCP起始地址/数量 | 100 / 100 | 分配`192.168.20.100–199` |
| 防火墙区域 | `lan` | 保留LAN管理访问 |

保存并应用后，管理地址会改变。让电脑重新获取地址，再访问`http://192.168.20.1`。确认电脑的网关和DNS均为`192.168.20.1`。在默认配置下，dnsmasq会提供地址和DNS；若已有自定义DHCP选项3或6，删除旧值或改成这台OpenWrt的LAN地址。相关字段见[官方DHCP与DNS说明](https://openwrt.org/docs/guide-user/base-system/dhcp)。

为了只验证本示例的IPv4路径，暂时关闭这个测试LAN的RA、DHCPv6和NDP服务，并停止WAN6；主路由原网络保持原状。IPv6地址不只有DHCPv6一种来源，不能只关闭DHCPv6就认为IPv6已停用。后续需要IPv6时应独立配置并验证，参照[官方IPv6文档](https://openwrt.org/docs/guide-user/network/ipv6/configuration)。

### 3. 配置WAN与防火墙，先验证直连

把主路由LAN口接到OpenWrt WAN口。在“网络 → 接口”将WAN设为**DHCP客户端**，绑定实际WAN设备，归入`wan`区域。不要把WAN网口加入LAN桥。

WAN应获得`192.168.1.x`地址、`192.168.1.1`默认网关和上游DNS。首次配置保留“使用对端通告的DNS”；确认上游解析可用以后，再添加确实可达的自定义DNS，不直接套用一组公共地址。

在“网络 → 防火墙”确认：LAN允许向WAN转发，WAN区域启用IPv4地址伪装（masquerading）；WAN入站仍保持拒绝，不对上游网络或互联网开放管理后台与代理控制端口。默认路由配置可参照[OpenWrt路由设备说明](https://openwrt.org/docs/guide-user/network/openwrt_as_routerdevice)。

**此时还不启动OpenClash。** 测试电脑应能获取`192.168.20.x`，访问主路由管理页及原本可访问的网站。若直连不通，先检查接口绑定、网段、WAN租约、DNS及防火墙，不用代理插件掩盖基础网络问题。

### 4. 从维护者仓库安装OpenClash

OpenClash是第三方插件，安装入口是[维护者GitHub仓库](https://github.com/vernesong/OpenClash)及其[Releases](https://github.com/vernesong/OpenClash/releases)，不是OpenWrt自带功能。核对所用发行版的依赖和包格式：OpenWrt 25.12使用APK；旧24.10使用IPK/opkg，不能混装。安装时以当前发布说明为准。

以下命令在**OpenWrt的SSH终端**执行，适用于本示例25.12＋firewall4，不是在电脑终端直接安装：

```sh
apk update
apk add bash dnsmasq-full curl ca-bundle ip-full ruby ruby-yaml kmod-tun kmod-inet-diag unzip kmod-nft-tproxy luci-compat luci luci-base
```

执行后检查每项是否安装成功。`dnsmasq-full`与原精简版可能冲突；若出现冲突，先下载并确认完整包可用、保存DHCP配置，再按发布说明替换。期间地址和DNS服务可能短暂中断，继续使用有线电脑维护。内核模块必须与当前固件内核匹配，出现版本不匹配时不要强制忽略依赖，应更新到匹配的固件或软件源。

在电脑下载当前Release的`.apk`，用SFTP或SCP上传到路由器`/tmp/openclash.apk`，再执行：

```sh
apk add --allow-untrusted /tmp/openclash.apk
```

`--allow-untrusted`用于安装未由OpenWrt软件源签名的外部包，所以只对刚从维护者Release取得并核对过来源的文件使用；不要对不明文件照搬。该参数见[官方APK说明](https://openwrt.org/docs/guide-user/additional-software/apk)。如安装器报冲突，先读报错和对应Release指引，不随意覆盖其他系统文件。

刷新LuCI，进入“服务 → OpenClash”。在“插件设置 → 版本更新”核对CPU架构并安装对应Mihomo内核，确认内核文件可用。然后检查运行日志中的依赖状态；界面可打开不代表内核已经能启动。

### 5. 导入兼容订阅并设置DNS

在“服务 → OpenClash → 配置订阅”新增名称和服务商提供的**Clash/Mihomo订阅地址**，保存后手动更新。也可在“配置管理”上传该格式的完整YAML，选择该配置作为当前配置。

检查节点、策略组和规则是否完整，再启动。首次采用**Fake-IP（非TUN）＋规则模式**；它与全局代理模式不同，不代表所有连接都走节点。“插件设置 → DNS设置”的本地DNS处理选择“Dnsmasq转发”，让客户端先查询`192.168.20.1`，由插件转发至内核DNS。保留配置中可用的DNS上游，不再同时安装其他DNS劫持或代理插件。选项与操作路径见维护者的[模式说明](https://github.com/vernesong/OpenClash/blob/dev/.github/skills/openclash-user-guide/08-settings-mode-traffic.md)、[DNS说明](https://github.com/vernesong/OpenClash/blob/dev/.github/skills/openclash-user-guide/09-settings-dns-ac-ipv6.md)和[订阅管理说明](https://github.com/vernesong/OpenClash/blob/dev/.github/skills/openclash-user-guide/12-subscribe-config.md)。

首次验证时，暂停测试电脑上另一个代理客户端，并将浏览器安全DNS、系统私人DNS恢复为自动，测试后按需要恢复。这样能区分路由器DNS与客户端自带DNS路径。订阅地址含访问凭据，不要截图公开，也不要把注册邀请链接填进订阅栏。

## 八、节点选择建议

先选一个已知能连接的节点，在OpenClash仪表盘中手动指定。按目标应用验证，而不是预设某个国家一定更快、某种协议一定适合所有路由器。

本示例需要通用Clash/Mihomo配置，可从[Clash订阅机场资料](/rankings/clash/)检查兼容性；如果服务只提供官方客户端，需先确认客服是否提供路由器可用的订阅。涉及ChatGPT或流媒体时，分别查[带日期AI记录](/rankings/chatgpt/)和[流媒体记录](/rankings/streaming/)，不能以“连接成功”代替目标应用可用。

## 九、优化技巧

### 先逐项验证，再增加设备

| 验证项目 | 怎么看 | 出错时先检查 |
|---|---|---|
| 基础网络 | 电脑地址为`192.168.20.x`，网关/DNS为`192.168.20.1` | DHCP租约、网口和网段 |
| 域名解析 | `nslookup example.com 192.168.20.1`能返回结果 | dnsmasq、内核DNS监听、上游DNS |
| 规则分流 | 打开两个配置中分别设为直连和代理的网站，在仪表盘“连接”查看命中规则、策略组和出口 | 规则顺序、所选节点、客户端是否另开代理 |
| 应用功能 | 登录目标应用，测试对话、上传或视频播放 | 应用地区规则、订阅、节点，不能只看Ping |
| 可恢复性 | 停止OpenClash后原直连网站仍可用；电脑接回主路由仍正常 | 残留DNS设置和路由器日志 |

`nslookup`只证明这一次指定服务器的解析结果，不证明所有应用都采用该DNS，更不证明没有绕过代理。观察日志、连续使用和你常用时段的表现；这些是读者自行验证步骤，不是本站测试结果。

### 回滚方法

1. 需要立即恢复上网时，电脑切回原主路由Wi-Fi或LAN，并把手动IP、网关和DNS恢复为自动。这一步不依赖OpenWrt还能否登录。
2. 在OpenClash停止插件，确认原直连网站恢复。若DNS仍异常，检查插件DNS恢复功能及运行日志，再恢复安装前的DHCP/DNS配置。
3. 若接口配置改错，用有线电脑接OpenWrt LAN，按当前LAN网段设置临时地址后登录；按同设备、同版本保存的备份恢复并重启。完全无法管理时，使用该设备官方恢复说明。
4. 完成验证后再导出新备份。恢复配置不会自动重装插件和内核，也不要把不同设备的备份直接覆盖进去。

## 十、常见问题 FAQ

### 必须刷机吗？

不一定。确切型号的原厂固件如果已有匹配VPN客户端，可走厂商方案；已运行受支持OpenWrt的设备也不需要再次刷写。品牌名称不能替代型号和硬件版本检查。

### 二级路由就是旁路由吗？

本文是两个网段、WAN接主路由、LAN带下游设备的二级路由。同网段旁路由常需客户端改网关/DNS，或者改主路由DHCP与路由；其回程路径和NAT配置不同，不能照搬本文地址表。

### 为什么原Wi-Fi上的手机没有变化？

原Wi-Fi仍由主路由直接提供。本文只接管OpenWrt下游设备；需要无线接入时，应使用OpenWrt受支持的无线功能，或在其LAN侧连接独立AP，不把主路由LAN与下游LAN再次桥接。

### 支持OpenVPN或WireGuard就能导入Clash订阅吗？

不能。它们的配置格式和运行组件不同；应取得实际客户端支持的配置。不要因为后台有“VPN”菜单就购买一个未确认兼容的订阅。

### 路由器设置后为什么游戏或投屏异常？

可能来自双重NAT、跨网段发现、UDP规则、IPv6或节点线路。先接回原主路由对照，再查看具体连接和规则；不能一概归因于硬件性能。

## 总结

先核对设备和固件，再完成直连、订阅、DNS及规则验证。本示例保留主路由，让一台电脑在独立网段试用OpenWrt与OpenClash；确认应用正常、可恢复后再增加设备。需要同网段旁路由或替换主路由时，应按对应拓扑重新设计地址与转发路径。

## 使用风险提示

外网应用的可用性受客户端、机场节点、DNS、账号、浏览器、平台状态和本地网络影响。本文只提供常见排查步骤，不保证任何节点或服务长期可用。涉及工作、学习和账号安全时，请保留备用方案。

很多用户会遇到这种情况：Google 能打开但 YouTube 卡，YouTube 能看但 GitHub 拉不动，Gmail 登录异常，或者只有某个软件不走代理。单应用打不开时，不要直接判断“机场坏了”，要先定位是哪一层出问题。

## 快速判断表

| 现象 | 待核对的环节 | 先做什么 |
|---|---|---|
| Google 打不开 | 客户端连接、目标请求的规则与DNS结果 | 记录错误，在客户端查看该请求是否出现及走向 |
| YouTube 卡顿 | 视频清晰度、设备/浏览器、网络吞吐与连接情况 | 用同一视频比较清晰度和节点，每次只改一项 |
| GitHub 网页能开但 Git 拉取失败 | 终端代理设置、SSH/HTTPS方式、鉴权或服务状态 | 保留Git报错，先区分连接失败与权限失败 |
| Gmail 登录异常 | 登录错误、账号安全提示、浏览器或连接 | 先阅读官方提示，不把额外验证直接归因为节点 |
| 只有 App 不可用 | App是否读取系统代理、分流规则与权限 | 查看目标请求的连接记录，再决定是否需配置应用代理或TUN |
| 开代理后国内网站慢 | 国内请求是否被代理、实际规则与其他占用 | 查该请求命中的规则，保存设置后做单项对照 |

## 第一步：先测基础连接

按顺序测试：

1. 记录出错网址或应用、时间、错误提示、客户端版本、当前配置和节点。分享日志时删除账号、令牌和个人订阅地址。
2. 查看目标平台状态页或帮助说明；若已公告故障，先按官方进展处理。
3. 确认套餐未到期、配置已启用、节点已选中，且没有多套代理设置互相覆盖。若订阅过期或更新失败，先处理订阅。
4. 对浏览器检查系统代理与独立代理插件；对其他应用检查它实际使用的代理方式。
5. 在同一设备、网络和节点下复现一次，查看客户端中的目标连接、命中规则与错误。
6. 需要比较模式或节点时，每次只改一项，记录结果并恢复原设置。全局模式也需在全局策略组选择节点，且不会自动让所有应用进入代理。

同一节点下全局可用、规则不可用，是继续检查目标请求分流与DNS结果的线索，不能仅凭这一现象排除其他故障。系统代理、TUN与规则/全局模式是不同设置。[Clash Verge Rev快速入门](https://www.clashverge.dev/guide/quickstart.html)、[Mihomo运行模式](https://wiki.metacubex.one/config/general/#运行模式)

## Google 打不开

优先检查：

- 系统代理是否开启。
- 浏览器是否使用了独立代理插件。
- Clash 或 v2rayN 是否选中了可用节点。
- 日志是否明确显示域名解析失败；没有记录时不先断言DNS被污染。
- 是否同时运行多个代理软件。

如果所有节点都打不开 Google，建议先看 [Clash订阅导入失败排查](/posts/clash-subscription-troubleshooting/)。

## YouTube 打不开或很卡

先记录是首页无法加载、视频不能播放，还是播放后缓冲；这些现象需要分别检查：

- 用同一视频降低清晰度，再对比其他浏览器或应用；分别记录结果。
- 如需比较节点，保持设备、网络、视频和清晰度相同，不按地区名称预判速度。
- 若怀疑时段相关，记录不同日期和时段，不能仅凭一次卡顿判断晚高峰拥堵或丢包。
- **流量计费倍率影响套餐额度消耗，不是网速或卡顿指标。** 例如2倍率表示使用1GB扣2GB；具体按所选服务当前规则核对。
- Speedtest与实际播放是不同操作。可参照[YouTube官方视频错误排查](https://support.google.com/youtube/answer/3037019?hl=en)检查连接和浏览器，再验证实际播放。

需要专门看视频和流媒体，可以参考 [流媒体机场榜](/rankings/streaming/)。

## GitHub 打不开或 Git 拉不动

开发者常见问题是浏览器能打开 GitHub，但终端、IDE、Git、npm、Docker 不走代理。

排查重点：

- 浏览器和终端是否使用同一个代理。
- Git HTTPS 是否配置了代理。
- SSH 连接是否需要单独配置。
- 工具是否读取系统代理，客户端连接记录里是否能看到该工具的请求。
- 公司网络、防火墙或 DNS 是否拦截。

GitHub官方提供[连接问题排查](https://docs.github.com/en/get-started/using-github/troubleshooting-connectivity-problems)，包括防火墙、代理与网络检查。HTTPS与SSH分别核对；权限、密钥或证书错误不能一律用换节点处理。若工具不读取系统代理，可按工具文档配置代理，或按客户端官方教程评估TUN；不要同时修改多项设置。

## Gmail 登录异常

先按屏幕上的具体提示区分连接失败、密码或验证问题：

- 阅读Google账号安全提示，并按[官方登录问题入口](https://support.google.com/accounts/troubleshooter/2402620?hl=zh-Hans)选择对应情况。
- 若显示需要验证或账号受限，按账号流程处理，不把换国家作为解决账号限制的步骤。
- 若网页加载失败，在保留账号与网络条件的情况下，使用干净浏览器配置检查扩展影响；不必先清空所有账号和浏览数据。
- 若官方确认平台故障，按其进展处理；没有官方信息时，仅记录自己遇到的现象，不声称服务大面积异常。

## 常见问题

### 为什么 Google 能开但 GitHub 不能

一个站点可用只能说明该次请求成功。先记录GitHub的具体错误并查看对应请求；网页与Git命令分开检查，再做同设备、同节点的模式或网络对照。

### 为什么浏览器能用，App 不能用

浏览器与App可能使用不同的代理方式。先核对应用设置与目标连接记录；需要TUN时按客户端文档处理权限和路由，完成后验证该App的实际操作。

### 为什么换节点后 Gmail 要验证

仅凭先换节点、后出现验证，无法确定原因。先按Google的提示完成账号核查；固定其余条件做对照，不连续更换账号、地区和浏览器后猜测是哪一项导致。

### 一个机场能解决所有应用吗

不一定。Google、YouTube、GitHub、Gmail、ChatGPT、Netflix 的要求不同。依赖工作或学习的用户最好准备备用机场。

## 总结

单个应用打不开时，先保留错误，再检查官方状态、客户端连接和目标请求。用同一环境逐项对照规则、节点、浏览器或网络；账号、付款、地区支持与连接问题分别处理。Google可用不代表AI服务已通过验证，具体见[AI工具排错](/posts/ai-tools-not-working/)。
